# NEON PROTOCOL — CONTENT QA GUIDE

Используй этот гайд для автономного аудита контента. Возвращай структурированный отчёт в конце.

---

## Контекст системы

**Стандарт диалогов**: Bibirevo Standard (все NPC используют DialogueBuilder)
**Валидаторы**: `npm run test:world` — структура деревьев, `npm run test:quests` — квестовые ссылки
**Районы**: 17 районов, каждый в `src/logic/world/<id>/index.ts`
**Квесты**: `src/logic/questData.ts` — QUEST_LIBRARY
**Лор-фрагменты**: `src/logic/intelFragments.ts`

---

## Шаг 1: Запусти автоматические валидаторы

```powershell
# Структура диалоговых деревьев всех 17 районов
& ".\node_modules\.bin\jiti.cmd" ".\scripts\validate-dialogues.ts"

# TypeScript типы (0 ошибок)
& ".\node_modules\.bin\tsc.cmd" --noEmit --project tsconfig.json
```

Если есть ошибки — исправь их первым делом. Не продолжай пока оба теста не зелёные.

---

## Шаг 2: Аудит диалогового дерева (на каждый NPC)

Для каждого NPC в районе проверь:

### Структурные требования (ОБЯЗАТЕЛЬНО)
- [ ] Есть хотя бы 2 варианта нейтрального приветствия (`neutral` пул)
- [ ] Есть хотя бы 1 приветствие для `hostile` состояния (если NPC агрессивный по лору)
- [ ] Каждая ветка диалога кончается либо квестом, либо `[Уйти]`
- [ ] Нет "мёртвых концов" — опций без `next` node
- [ ] Квест не предлагается в первой фразе — сначала характер NPC

### Тон и голос фракции
| Фракция | Тон | Запрещено |
|---|---|---|
| EU_Syntax | Академический, точный, технический | Жаргон Redundants |
| Net Drivers | Бюрократический, протокольный, сухой | Эмоции, лирика |
| Voskhod | Ностальгический, советский эстетизм | Циничность |
| GigaBank | Корпоративный, хищный, улыбчивый | Прямые угрозы |
| Redundants | Street-style, хаотичный, с юмором | Академизм |
| Дзен-ЦОД | Медитативный, метафоры природы/кода | Агрессия |

### Квестовая логика
- [ ] Квест имеет минимум 2 пути (Technical / Social / Combat)
- [ ] Есть check на уровень (`requireMinLevel`) или квест (`requireQuestId`)
- [ ] Награда в Bits соответствует рангу (SK: 20-80, Junior: 80-150, Mid+: 200+)
- [ ] После завершения квеста — диалог меняется (используется `requireCompletedQuestId`)

### Лор-консистентность
- [ ] NPC знает только то что релевантно его фракции и позиции
- [ ] Отсылки на другие районы логичны (торговля, слухи, связи NPC)
- [ ] Нет "метаигровых" фраз ("нажми кнопку", "посмотри в меню")
- [ ] Имена собственные совпадают с остальными файлами района

## Шаг 3: Проверка квестовых цепочек

Для каждой квестовой цепочки (серии квестов от одного NPC):
- [ ] Квест #1 имеет `awardQuestId` → квест #2 имеет `requireQuestId` = то же значение
- [ ] Нет "пустых" quest ID (придуманных, но не зарегистрированных в QUEST_LIBRARY)
- [ ] После `completeQuestId` → NPC показывает follow-up диалог, а не первый экран

### Проверь в коде руками:
```typescript
// Например, для района bibirevo
import { bibirevo } from './src/logic/world/bibirevo/index';
// Найди все awardQuestId в dialogues
// Проверь что они есть в questData.ts → QUEST_LIBRARY (или DISTRICT_NARRATIVE_QUESTS)
```

---

## Шаг 4: Проверка Intel Fragments

Если в диалоге используется `awardIntelId`:
- [ ] ID фрагмента существует в `INTEL_FRAGMENTS` в `src/logic/intelFragments.ts`
- [ ] Тип фракции фрагмента совпадает с фракцией NPC
- [ ] Контент фрагмента соответствует тону самого диалога

---

## Шаг 5: Playtesting route (новый игрок)

Пройди этот маршрут в голове или в браузере:

```
START: Hub → Bibirevo → Altufyevo

Для каждого NPC:
1. Открыть диалог
2. Дойти до квестовой опции
3. Убедиться что квест доступен (нет блокировки без причины)
4. Завершить квест
5. Вернуться — убедиться что диалог изменился
```
