# Гайдлайны по Тестированию и Внедрению Новых Фич

Этот воркфлоу предназначен для Джуниоров (младших агентов) для предотвращения поломки "чистой" архитектуры Neon Protocol и минимизации рисков при деплое на платформу Amvera.

## 1. Базы Данных (Prisma + SQLite) и Миграции

### Проблема: SQLite не переваривает часть миграций
SQLite имеет строгие ограничения на изменение схем таблиц, содержащих данные. Из-за этого при деплое скрипт `npx prisma db push --accept-data-loss` может привести к падению сервера:

- **ОЧЕНЬ ВАЖНО:** Не добавляйте обязательные новые столбцы `(Например: name String)` без дефолтного значения в уже существующую таблицу! SQLite не умеет их добавлять в таблицы с данными.
- **Работа с JSON:** При добавлении новых полей типа `Json`, делайте их **необязательными** (`Json?`), а не обязательными без дефолтных значений. Пример:
  ```prisma
  // ПЛОХО (упадет на Amvera, так как в SQLite нет валидного варианта записи JSON дефолта)
  newField Json @default("{}")

  // ХОРОШО:
  newField Json?
  ```
- Для любых остальных типов при расширении схемы всегда используйте `@default()` (например `score Int @default(0)`), иначе сервер не сможет запустить базу. 

### Правила добавления моделей:
1. Отредактировал `schema.prisma`.
2. Обязательно запусти локально проверку накатывания схемы (без нее заливать в мастер НЕЛЬЗЯ):
   ```cmd
   cmd /c npx prisma db push --accept-data-loss
   ```

## 2. Архитектура React Взаимодействий

### Хук State (`useGameState.ts`)
Все ключевые состояния (монеты, статы, HP, инвентарь) принадлежат глобальному стейту. Никогда не создавай `useState` для глобальных переменных глубоко в дочерних файлах. 
Все изменения передаются сверху-вниз (Bottom-up flow через пропсы, типа `onCompleteQuest` или `onTravel`).

### Индексация (`App.tsx`)
После недавнего рефакторинга монолита, `App.tsx` выполняет роль роутера компонентов.
- НЕ добавляйте новые сложные `useEffect` с логикой получения данных напрямую в `App.tsx` — перенесите это в хуки.
- Если создаете новую View (например, `StoreView.tsx`), выносите JSX туда, и подключайте как функцию в роутер.

## 3. Статический Анализ Кода (TypeScript)

Если вы написали новый код и изменили типы, перед коммитом вы **ОБЯЗАНЫ** запустить проверку типизации:

// turbo
```cmd
cmd /c npx tsc --noEmit
```
Если есть ошибки Type mismatch (например в интерфейсе `QuestData` или в пропсах компонента), вы должны их устранить. 
TypeScript — первая и главная линия защиты от багов интерфейса React.

## 4. Сборка (Build)

И наконец, перед тем как утверждать, что "фича готова", проверьте, что сборщик Vite способен всё это превратить в рабочий бандл.

// turbo
```cmd
cmd /c npm run build
```
Только после прохождения всех 4 этапов вы можете коммитить изменения!
