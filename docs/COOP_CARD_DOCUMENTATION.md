# Документация: карты и справочник в кооперативном режиме

В режиме **кооп** (стартап, полигон `coop_yard`) у каждого игрока своя **роль**: Developer, QA, Admin или PM. От роли зависит, какие **протоколы** (боевые карты) вообще доступны в конструкторе колоды и в этом справочнике.

## 1. Каталог роли

**Каталог** — это множество `id` карт, разрешённых для вашей роли. Он задаётся в коде игры (`getCoopRoleCatalogIds` в `sessionMode.ts`):

| Роль | От чего зависит каталог |
|------|-------------------------|
| **Developer** | Выбранный **языковой стек** (Java / Kotlin / Python / Go): ядро языка, пакеты библиотек из конструктора, без чужих зон (инфра/софт/реакции не из вашей роли). Для Spring-карт каталог пересекается с `SPRING_CARD_LIBRARY`, если id входит в стек. |
| **QA** | Реакции, DEFENSIVE и связанные акценты: дефект-пайплайн, регресс, периметр тестов и т.д. |
| **Admin** | SCRIPT и INFRASTRUCTURE (периметр, shell, кластеры, прокси и т.п.). |
| **PM** | SOFT-скиллы и процессные карты (фокус, дедлайны, синхронизация команды и др.). |

В справочнике во вкладках **JAVA_CORE**, **SCRIPTS**, **SPRING_BOOT**, **INFRA**, **SOFT_SKILLS**, **TESTS** в коопе показываются **только** карты из каталога вашей роли. Карты других ролей в этих списках **не отображаются** — это не баг, а разделение зон ответственности.

## 2. Открыто и закрыто (заметки по картам)

Для каждой карты из отфильтрованного списка игра проверяет, есть ли её `id` в множестве **открытых протоколов** (`discoveredCardIds`).

- **Открыто (discovered)** — карта уже «засветилась» у персонажа: есть в **активной колоде** или в **инвентаре** (уникальные экземпляры). В списке слева видно **название** и **описание** справа; строка подсвечивается как открытая.
- **Закрыто (locked)** — карта входит в каталог роли (теоретически доступна в конструкторе или как награда), но вы её ещё **не получили** в колоду/инвентарь. В списке отображается маска `????????????`, подробный текст справа недоступен до открытия.

Таким образом, справочник в коопе отвечает на два вопроса сразу: *«что моей роли вообще положено по лору системы»* (каталог) и *«что я уже несу с собой»* (открыто).

## 3. Как открыть новую заметку

- Добавить карту в **колоду** в конструкторе (если id уже в каталоге и карта доступна в сетке наград/магазина).
- Получить карту **наградой** за сегменты полигона, квесты или события — она попадает в инвентарь и помечается как открытая.
- После синхронизации сохранения множество открытых id обновляется вместе с колодой и инвентарём.

## 4. Режим SANDBOX в коопе

В песочнице в список доступных для сборки протоколов попадают только карты, которые **уже открыты** и при этом относятся к **вашему кооп-каталогу** (дублирование правил фильтра).

## 5. Константы размера колоды (кооп)

- **Минимум** 30 карт в стартовой колоде при создании персонажа коопа (если уникальных id в каталоге меньше — добор по правилам в `sessionMode.ts`).
- **Максимум** 200 карт в колоде в коопе в конструкторе.

Подробности реализации: `sessionMode.ts` (`COOP_DECK_MIN_CARDS`, `COOP_DECK_MAX_CARDS`, `buildStarterDeckForSession`, `buildCoopProtocolDocCards`).

## 6. Связь с кодом

| Механика | Файл / символ |
|----------|----------------|
| Каталог по роли | `getCoopRoleCatalogIds`, `DEVELOPER_STACK_BROWSE_IDS`, `COOP_*_CATALOG_IDS` |
| Список карт для справочника | `buildCoopProtocolDocCards` |
| UI справочника | `Documentation.tsx`, фильтр `filterCoopCatalog`, классы `discovered` / `locked` |
| Источник «открытых» id | `App.tsx`: `discoveredCardIds` ∪ id из `activeDeck` |
