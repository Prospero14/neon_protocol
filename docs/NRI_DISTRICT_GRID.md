# NRI: сетка квартала (district grid)

Дизайн-документ: провал в район, типовые клетки, стили квартала, стыковка тайлов, микро-анимации и план реализации.

Связанные контракты: `zoneKey` топ-уровня не меняем; сабзоны — `{parentZoneKey}__{row}_{col}`; achievements/travel — `rootMapZoneKey()` для «Картографа».

---

## 1. Видение (UX мастера)

### 1.1 Два уровня карты (гибрид)

| Уровень | Что видит пользователь | Данные |
|---------|------------------------|--------|
| **Neon City** | Мегарайоны, районы, корп-блоки | `parentZoneKey IS NULL` |
| **Квартал** (провал) | Сетка клеток на всю площадь родителя | `parentZoneKey = <район>` |

Мастер на обзоре выбирает район, называет его (напр. «Чайна-таун»), проваливается внутрь.

### 1.2 Сетка клеток

- При seed район **полностью** покрыт **одинаковыми квадратами** (`placeType: generic`).
- Периметр — клетки `exit` (просвет / улица в соседний квартал), не «стена».
- Мастер для каждой клетки:
  - **переименовывает** (напр. «Ресторан Лотос»);
  - задаёт **тип постройки** (`placeType`);
  - при необходимости POI, цвет (опционально).
- Пример композиции: мост → дорога → рестораны по бокам → секонд → переулок → дома → парк → площадь → край с проёмом.

### 1.3 Стиль квартала (`districtStyle`)

Визуальный язык **всего** квартала. Примеры:

| `districtStyle` | Назначение |
|-----------------|------------|
| `chinatown` | вывески, красно-золотой неон, фонари |
| `residential` | спальный, умеренный мусор |
| `corp_clean` | вылизано, без бомжей и мусора |
| `slum` | грязь, лом, импланты-хлам |
| `industrial` | трубы, ржавчина |
| `park_mixed` | зелень, тише |

По умолчанию выводится из `zoneType` родителя; мастер может переопределить на родителе (`districtStyle` на топ-зоне).

### 1.4 Сочетание клеток (не «кубики»)

Отрисовка учитывает **соседей** (4-связность в сетке):

- дорога стыкуется с дорогой / перекрёстком;
- фасады shop/restaurant/house «смотрят» на ближайшую дорогу;
- переулок — узкий тёмный проход;
- парк/площадь — мягче границы, общий тон;
- `exit` — просвет между «домами», дорога вдаль.

Реализация: `districtTileVisual.ts` — pure functions `(tile, neighbors, style, decay) → SVG layers`.

### 1.5 Градиент «центр → край»

`decay = f(distanceFromCenter, districtStyle)`:

- **corp_clean**: низкий decay везде;
- **slum / окраина**: к краю больше мусора, бомжей, сломанных имплантов;
- **residential**: умеренно.

Детерминизм: `hash(zoneKey)` для «где бомж», чтобы у всех за столом одинаково.

### 1.6 Микро-анимации (2–3 кадра)

| `placeType` | Анимация | Техника |
|-------------|----------|---------|
| road + parking | фары машин on/off | CSS `steps(2)` |
| house | мигание окон (обычные / фиолетовые) | CSS |
| restaurant | мерцание неона / искры | CSS opacity |
| park | покачивание кроны | CSS transform |
| alley / generic | статичные пропсы (бомж, пьяница, мусор) | SVG + decay |

**Лимиты производительности:**

- анимации только в **district mode**;
- не более **~40** одновременных CSS-анимаций (видимые клетки);
- остальные — статичный кадр 0;
- city mode — **без** сетки и жизни.

### 1.7 Метки и NPC

- В district mode мастер **ставит метки** (host/player), координаты в % родителя или привязка к клетке.
- Travel / позиция игрока — `zoneKey` клетки или родителя (контракт сохраняем).

### 1.8 Удаление клеток

- Не «удалить если нет игроков» как основной сценарий.
- **Сброс** клетки: `placeType → generic`, имя → «Клетка r,c».
- Delete: при наличии игроков — **перенос** на `parentZoneKey`, не блок.

## 2. Модель данных

### 2.1 Поля `NriMapZone`

| Поле | Где | Описание |
|------|-----|----------|
| `parentZoneKey` | сабзона | родитель |
| `placeType` | сабзона | тип клетки (см. enum) |
| `districtStyle` | топ-район | стиль квартала |
| `gridRow`, `gridCol` | сабзона | индекс в сетке (для соседей) |
| `zoneType` | все | gameplay-тип района (mid, slum, corp…) — **не путать** с `placeType` |

### 2.2 `placeType` (MVP enum)

```
generic | road | bridge | crossing | house | restaurant | shop | secondhand
alley | park | plaza | parking | metro | exit
```

### 2.3 Ключ сабзоны

```
{parentZoneKey}__{row}_{col}
```

Пример: `watson_kabuki__3_5`

## 3. API

| Метод | Назначение |
|-------|------------|
| `GET .../map/zones` | только топ-зоны + `subTileCount` |
| `GET .../map/zones?parent=<key>` | клетки квартала |
| `PATCH .../map/zones/:key` | `name`, `placeType`, `districtStyle`, `pois`, `color` |
| `POST .../map/zones` | (legacy) создать клетку — позже replace на regen grid |
| `DELETE .../map/zones/:key` | сабзона: игроки → родитель |

Seed: `MAP_LAYOUT_VERSION = v6-district-grid`, merge missing без wipe.

## 4. Стек и оптимизация

**Менять не нужно:** TypeScript, React, Vite, SVG, Node, Prisma, SQLite, REST JSON.

| Принцип | Реализация |
|---------|------------|
| Lazy load | топ на обзоре; сетка по `?parent=` при провале |
| SVG defs | один паттерн на тип+стиль, не на клетку |
| Анимации | CSS на `<g>`, лимит счётчиком |
| Логика стыковки | pure TS в `shared/`, тесты vitest |
| Генерация сетки | `nriNeonCitySubzonesGen.ts`, offline `tmp/gen-zones.mjs` |

Canvas/WebGL — только если >500 анимированных клеток на экране (не MVP).

## 6. Критерии готовности MVP (фаза A)

1. Провал в район показывает **полную сетку** generic-клеток.
2. Мастер меняет **имя** и **placeType**; вид клетки меняется.
3. Мастер задаёт **districtStyle** на районе.
4. Метки работают в district mode.
5. Обзор города не грузит тысячи клеток (lazy).
6. Build и тесты зелёные.
